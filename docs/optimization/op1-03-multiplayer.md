# 第 2 轮优化 · 联机与身份

> 本文件收录第 1 轮反馈实施中与「联机与身份」相关的条目，原始意见与总索引见 op1.md。掉线身份令牌续局、房间内重名拒绝与 nonce 防双开抢占、对战统计独立卡片框、聊天清空（保留待回应提议）。

## 反馈 9：创建后规格栏着重提示 + 掉线身份识别续局 + 多局与历史完整性检查 + 征求新功能

### 你的想法

1. 点击创建房间后规格应着重提示：弹消息提醒，或做动效拉长规格栏、显示"提议规格"、颜色转为当前玩家颜色（蓝/黄我来定）；
2. 一方退出后应显示对方离线；对方再次加入要确定是否是刚才的用户——建议每次用户写完昵称后默认分配一个 hash 值来识别；是同一用户就接着刚才的对局继续，不是就让他等待；
3. 多打几局棋，检查每个小局能否独立设置规格、左侧历史棋局信息是否完整；
4. 推荐可加入的新功能/界面元素（如旁观功能）；**并要求我以后对其反馈做理性分析，不合理的地方要及时提出**。

### 我的想法与实现（含两处未完全照办的设计决策）

1. **规格栏提示**：没选弹窗（打断操作流、遮内容），采用你的第二方案——创建/加入房间后规格栏**以玩家专属颜色高亮**（A 蓝 / B 橙，与比分卡同色系），并播放一次"拉伸"动效（scaleX 0.85→1.03→1）；系统提示也补上规格信息。技术上用 `key=房间号` 触发重挂载动画，零额外状态。
2. **身份识别**：没采用纯昵称 hash——**同昵称的任何人都能冒充**，这不安全。改为**身份令牌持久化**：创建/加入成功后把 `{昵称, 令牌}` 存进浏览器 localStorage；之后再进房时同名同浏览器自动携带令牌 → 服务端识别为同一玩家，恢复其身份与对局状态；换浏览器或换昵称=新用户，此时若座位被掉线玩家保留（90 秒宽限）会收到"房间已满：…请稍后重试"的等待提示。掉线方比分卡显示"离线"、系统消息提示等待重连（原有能力），重连后局面（棋盘/局数/回合状态）原样保留。
3. **多局检查**：新增 `client/multi-round-test.mjs` 回归脚本，三局连打（4*4 默认 → A 提议 3*5 对方同意 → B 还价 2*2 对方同意），15 项断言全过：每局规格独立生效、历史条目字段完整（局数/规格/先手/比分/胜者/时间）、每局盒子分总和等于棋盘格数、大比分与各局胜者一致、投票开下一局后历史保留。

### 验证

- 服务端/客户端 `tsc` + ESLint 通过。
- `multi-round-test.mjs` 15/15；新增 `resume-test.mjs` 9/9（B 带令牌加入→打两手→掉线→陌生令牌被拒等待→同令牌重连恢复局数/棋盘/状态）。
- 浏览器实测：创建后规格栏蓝色高亮 + "提议规格"按钮 + 新提示文案；对手掉线后 B 卡显示"离线"、名字保留（截图确认；重连后短暂在线随后测试进程退出再次离线，属预期）。

## 反馈 18：对战统计独立成框 + 聊天清空按钮

### 你的想法

1. 对战统计单独用一个框，里面可滚动，多局后历史信息不至于把左侧撑长；
2. 聊天框加清空历史按钮，但不能删掉未处理的"请求对方同意"消息。

### 实现与验证

1. **对战统计卡片框**：从侧栏面板中独立为带边框的卡片（自身背景+阴影+圆角），历史列表限高 26vh 内部滚动。踩坑记录：第一版把它挪成了三栏网格的第 4 个子项，被自动排进中间列导致整页布局错位，已改回侧栏内的卡片方案。
2. **清空聊天**：聊天标题行右侧新增 🗑 按钮，触发服务端 `clear_chat`——仅保留 `kind='board-proposal'` 且状态为 `pending` 的消息（待回应的规格提议），其余普通消息与已处理提议全部清除；旁观者无权清空。前端通过 room_state 同步刷新。
- 新增断言：清空后普通消息消失 ✓、待回应提议保留 ✓。四套回归全部通过；浏览器实测布局恢复、卡片框与滚动正常。
