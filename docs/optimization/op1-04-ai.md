## 反馈 21：左上角规则弹窗 + 分支管理 + AI 接入落地（含 Berlekamp 策略）

### 你的想法

1. 左上角加"查看规则"按钮，弹出居中规则框，动效 UI 自定；规则同时用于 AI 提示词；
2. 先把不含 AI 的修改上传：开新分支提交推送，然后再加 AI；
3. （上轮规划确认）AI 条件改为最大边 ≥6；安全采用 BYOK 浏览器直连（开源场景密钥不能过服务器）；不要时间限制；其余按我的方案执行；
4. 调研井格棋策略（提供了 Berlekamp《The Dots-and-Boxes Game》PDF），写进 AI 提示词提升棋力；优化接入弹窗 UI；确保密钥安全；之后给 API 做双窗实测。

### 实现与验证

1. **规则弹窗**：`gameRules.ts` 导出 `GAME_RULES`（4 节 13 条）作为单一来源，"查看规则"按钮（左上角）弹居中模态（淡入上滑动效、Esc/背景点击/知道了关闭），AI 提示词直接引用同一常量。踩坑：App.tsx 内导出常量会破坏 fast-refresh，已拆到独立文件。
2. **分支管理**：`feat/enhancements` 分支提交并推送全部非 AI 修改（3995864），AI 完成后同分支二次提交。
3. **AI 接入**（`aiClient.ts` + App 集成）：
   - 显示条件 `max(rows, cols) >= 6`；操作区"接入 AI/断开 AI"按钮 + 状态行；
   - 设置模态重设计：分区布局、Key 显示/隐藏切换、HTTPS 强制（http 仅允许 localhost，防密钥明文跨网）、安全说明；**BYOK 安全模型**——Key 只存浏览器 localStorage、仅直连用户填写的地址、不经过游戏服务器；
   - 驱动状态机：自动确认/提议规格、准备、掷骰、轮到己方时调 LLM 落子、跟随对方投票；未填 Key 退化为随机陪练；输出非法/超时随机兜底，API 连续 3 次失败自动断开；
   - 接入后名字旁 🤖 标记并在聊天告知对方；棋盘可绘制 PNG 供视觉模型。
4. **AI 策略升级（源自 Berlekamp 书）**：提炼高阶策略写入提示词——控制权理论、长链法则（点数+双跳奇偶）、double-dealing 让 2 盒/闭环留 4 盒、硬心/半心施舍、终局全吃等；并新增**程序化战术分析** `analyzeBoard`：精确计算"立即得盒边/安全边/危险边"注入提示词，让模型基于确定事实而非自行推理棋面。
- 验证：双端 tsc/ESLint 通过、四套回归通过；浏览器实测 6*6 全自动对局（AI vs 机器人）完整打完 84/84 边（比分 11:25），全程零人工干预；提示词构建与战术分析经 tsx 单测验证（三边盒→立即得盒边、危险边判定均正确）。
- 事故记录：`git add -A` 误将提取的整本书文本提交到公开分支，已 amend + force-push 彻底清除；后续提取资料一律放仓库外。
5. **Qwen vs Qwen 双 AI 实测**：两个标签页分别接入同一 Qwen 端点（qwen-local，思考模式自动关闭后单步延迟约 0.7-2s），全流程零干预：A 提议规格 → B 自动同意 → 双方准备 → 掷骰（含同点重掷）→ LLM 逐边对弈 → 终局自动投票开下一局，已验证连续多局自主运转。首局比分约 22:8（先手与链权优势方胜出），对局节奏约 1-2 秒一步。

## 反馈 22：AI 请求被 uBlock 拦截（中转修复）+ 移除自动断开

### 你的想法

1. "他这边的 AI 总断"——附 DevTools 截图：大量 "blocked by CORS policy / ERR_FAILED"；
2. 自己认领原因："我知道了，是 uBlock 干的吧"；
3. AI 出错不要自动断开——开发 AI 就是用来斗蛐蛐的，出错就错吧。

### 排查与实现

1. **根因确认**：uBlock/隐私扩展会静默拦截"页面向陌生域名的跨域 POST"，正是控制台那种 "No Access-Control-Allow-Origin header + ERR_FAILED" 组合；服务器本身无问题（干净环境实测同一 API 完整对局 30:6）。
2. **中转修复**：LLM 请求改经游戏服务器 `POST /ai/relay` 哑转发——Key 随请求临时过一次（不存储、不记日志），仅允许 HTTPS/localhost、拒绝内网地址（SSRF 防护）、超时 65s；上游错误原因透传到 AI 状态行。浏览器只与自己游戏服务器通信，扩展不再拦截。已实测经中转的真实 Qwen 调用 200 正常。
3. **移除自动断开与出错计数**：LLM 出错/输出非法时随机兜底继续走，状态行只显示"待机/思考中"——斗蛐蛐模式贯彻到底。
4. **瞬时故障韧性**：中转超时放宽至 120s 并区分超时/连接错误；客户端对失败自动重试一次（1.5s 后）再兜底——上游繁忙/重启等瞬时抖动不再打断 AI 对局（实测：502 后恢复，重试即成功）。
5. **全模型强制禁止思考**：各服务商关闭思考的参数形状不同，采用"全家桶下发 + 剔除重试"——请求同时携带 Qwen（chat_template_kwargs）、GLM（thinking.type=disabled）、硅基流动（enable_thinking）、OpenRouter（reasoning）、OpenAI 推理系（reasoning_effort=minimal）五家的关闭参数；网关不认识返回 400/422 时自动剔除参数重发。deepseek-reasoner 等纯思考模型无法参数化关闭，需改用对话型模型名（deepseek-chat）。

### 验证

- 双端 tsc/ESLint 通过；curl 直打 `/ai/relay` 实测真实 Key 200 正常返回策略回答；用户重连 AI 即可从当前局面继续。
