# 第 2 轮优化 · UI 与布局

> 本文件收录第 1 轮反馈实施中与「UI 与布局」相关的条目，原始意见与总索引见 op1.md。布局三栏化、规格锁定遮罩、身份强调、按钮/字体三档制统一、计分牌、聊天极简化、复制兜底等全部视觉与交互改造。

## 反馈 1：布局调整 + 重开一局 + 征求建议

### 你的想法（原话归纳）

1. **最大问题是页面布局**，含三个子问题：
   - 房间聊天应该放在**最右侧**，不该放下方；中间棋盘那部分太宽，正好用聊天栏平衡；
   - **棋盘位置不突出**、**当前回合该轮到谁不突出**，要我斟酌后调整；
   - 左侧栏布局仍可调整。
2. 页面应有**重开一局**选项：**当且仅当两个选手都同意**时才重开；重开相当于重新来一局，**之前的记录不变**。
3. 希望给出页面/功能上的改进、增删建议。

### 我的想法与设计决策

**布局（三栏结构）**
- 原 `280px + 弹性` 两栏里，中间列独占约 1300px，棋盘（最大 8×8 约 690px）居左漂着，聊天沉在底部只有 160px 高——空间分配失衡。
- 改为 `290px | 弹性中列 | 320px` 三栏：左=控制台，中=对局信息+棋盘，右=聊天。棋盘在面板内水平垂直居中，中列不再被拉满，视觉重心回到棋盘。
- 棋盘区从"固定 500px 高的空面板"改为 flex 居中容器，棋盘外围留白对称，配合发光描边强调。

**回合指示（三层强调）**
1. 顶部比分区改为「A 卡片 — 圆形回合勋章 — B 卡片」：轮到谁，谁的卡片**金色描边上浮**并挂"行动中"徽章，勋章显示 A/B 大字和当前回合方颜色；
2. 比分下方一条**整宽回合横幅**（轮到 A=蓝色渐变、轮到 B=橙色渐变、结束=灰色），自己回合时显示"🎯 轮到你了！"并带呼吸光圈动画；
3. 轮到你时**棋盘面板外框同色发光**（glow-a/glow-b），视线不用离开棋盘也知道该谁走。
- 原来散落在 status-grid 里的 7 行小字（房间/规格/状态/先手/结果…）压缩成顶部的圆角信息 chips + 一行小字，给棋盘让出垂直空间。

**左侧栏分组**
- 三段式：`房间`（昵称/规格/房号 + 创建/加入）、`操作`（准备、掷骰、重开投票、退回首页，全部通栏按钮）、`对战统计`（压缩成单行摘要 + 可滚动列表，最高 34vh），sticky 跟随滚动。
- 历史条目从 5 行压缩为 2 行（标题行 + 先手/比分/结果行）。

**重开一局（服务端权威的投票制）**
- 原逻辑：对局结束后**任意一方**点"再来一局"就直接开下一局，另一方没有否决权——正和你说的"当且仅当双方同意"冲突，所以整个换成投票制。
- 覆盖两个场景（同一个投票通道 `vote_next_round`）：
  - **对局进行中**：任一方发起，双方都同意 → 清盘重开**本局**（roundNumber 不变，`roundHistory`/`seriesScore` 完全不动，即"之前的记录不会变"），回到准备→掷骰流程；
  - **对局已结束**：原来的"再来一局"按钮升级为"同意再来一局"，双方都同意 → `roundNumber+1` 开下一局，历史与大比分保留。
- 投票可随时**再次点击撤回**（toggle），避免误触；任一方掉线其票自动作废。
- 结算从"浮在右侧的小面板（还要 JS 量宽度决定显隐）"改为**全屏毛玻璃遮罩 + 居中结算卡**，结果、比分、同意按钮、双方投票状态一目了然；顺带删掉了 ResizeObserver 那套估算逻辑。

## 反馈 2：右侧聊天面板长度与中间棋盘底部对齐

### 你的想法

> 你要对齐右侧房间聊天面板的长度，和中间的棋盘那个最底下对齐不就可以了。

### 我的想法

- 这正是 CSS Grid 的 `stretch` 对齐能白拿的效果：`.layout` 从 `align-items: start` 改为 `stretch`，中列和聊天栏自动等高、底边天然对齐；
- 聊天栏不再用 `height: calc(100vh - 20px)` 硬绑视口（那会棋盘矮时聊天下探、棋盘高时聊天不够长），改为跟随内容列；
- 左侧栏保持 `align-self: start` 紧凑不跟撑。

### 改动与验证

- `App.css`：`.layout` → `align-items: stretch`；`.controls` 加 `align-self: start`；`.chat-panel` 删除 sticky/固定高度，仅保留 flex 列布局 + `min-height`。
- 实测（getBoundingClientRect）：中列 bottom=872px、聊天面板 bottom=872px，**像素级对齐**；左栏 631px 自适应内容。

## 反馈 10：下一局按钮文案 + 聊天/棋盘固定等高 + 输入框 Enter 确认 + 四个新功能拍板

### 你的想法

1. 玩完一局准备开下一局时，侧栏按钮应显示"我同意下一局"而不是"我同意重开"（附截图）；
2. 聊天框不应随消息增长，应固定长度、消息内部滚动；棋盘高度也固定，且始终和聊天框等长；
3. 其他输入框输入时也应支持 Enter 确认，但不要在界面上提示，默认即可；
4. 对上一轮推荐的功能拍板：回合倒计时 ✓、旁观模式 ✓（按我提的只读方案做）、对局回放 ✓、复制房间号/分享链接 ✓（注意 UI 美观）、音效 ✗（不做）。

### 我的想法与实现

1. **按钮文案**：侧栏重开按钮按阶段区分——进行中"我同意重开"、已结束"我同意下一局"，撤回文案统一"撤回我的同意"。这是上一轮文案动态化时漏改的按钮文字，属于纯疏漏。
2. **固定等高**：`.layout` 定义 `--lane-h: clamp(520px, calc(100vh - 170px), 940px)`，聊天面板与中间列（对局头部+棋盘）都绑定该高度——两者永远等长；聊天列表 `flex:1 + min-height:0` 内部滚动；棋盘区 `minmax(0,1fr)` 占满剩余高度，大棋盘内部滚动。≤1100px 断点下回退为堆叠布局（高度自适应）。
3. **Enter 确认**：昵称 Enter=提交失焦；规格 Enter=创建房间（lobby）/提议规格（房内）；房号 Enter=加入房间。均带输入法组词保护，不在占位文案中宣传。
4. **回合倒计时**：服务端 `TURN_TIMEOUT_MS`（默认 30s，环境变量可调、下限 5s）；对局中每手棋限时，超时服务端自动换对方行动并广播 `turn_skipped`；房间销毁时清定时器。前端横幅右侧显示 `⏱ Ns` 本地走秒。
5. **旁观模式**：满员时新用户自动以旁观者身份进入（只读棋盘与聊天；落子/投票/提议/发言全部被服务端拒绝）；头部显示"👁 旁观 N 人"；旁观者断线自动清理。注意：这替换了上一轮"满员拒绝等待"的行为——现在等待的方式是看棋。
6. **对局回放**：服务端每局记录 `moveOrder`（落子顺序）入历史；点击历史条目出现回放条（⏮ ◀ ▶自动 ▶ ⏭ + 进度 + 回到终局），按步截断棋盘显示，盒子归属取"完成该盒的那条边的主人"，正确还原任意中间局面。
7. **复制房间号/分享链接**：头部房间 chip 变为可点击按钮，点击复制 `Origin?room=XXXX` 链接并短暂显示"已复制 ✓"；打开带 `?room=` 的链接自动填入房号。

### 验证

- 双端 `tsc` + ESLint 通过；四套回归脚本全部通过（restart / proposal 14 项 / multi-round 15 项 / resume 9 项，其中 resume 的"满员拒绝"断言按新旁观行为更新）。
- 倒计时专项：独立端口起服务（`TURN_TIMEOUT_MS=2s`，被 5s 下限钳制）实测 4/4——超时自动换人、广播文案、新倒计时重置。
- 浏览器实测：对局横幅 `⏱` 实时走秒（且真实触发了一次"A 方超时，自动换 B 方行动"）；复制 chip 点击变"已复制 ✓"；结束后侧栏按钮显示"我同意下一局"；历史条目点击出现回放条，步进 2/40 时棋盘只剩前两手；`getBoundingClientRect` 实测中间列与聊天面板高度一致（730px = 730px）。

## 反馈 15：计分板做成积分牌样式 + 房间数据生命周期确认

### 你的想法

1. "共 N 局"也要强调，整块计分最好做成类似积分牌的样子，不然有点难看；
2. 询问：每局打完房间数据是不是就不保存了？这样挺好，房间号下次还能复用，整个游戏结束后直接清空房间相关数据即可。

### 我的想法与实现

1. 计分块重设计为**深色积分牌**：深蓝渐变底 + 内描边，"共 N 局"做成牌内半透明小徽章，比分数字改为白色 1.7rem 特粗（LED 计分牌质感），A/B 字母用浅蓝/浅橙保证深底可读。无溢出。
2. **确认 + 说明清空时机**：房间数据只存在服务器内存，不做任何持久化。清空时机是"房间没人了"（双方都离开，含掉线 90 秒宽限）——而不是"游戏刚结束的瞬间"，因为结算遮罩、历史回放、再来一局投票都依赖这份数据，刚打完就清会把这些功能全杀掉；"人走光再清"在效果上等价于"整个游戏结束后清空"。房间号删除后即可被随机重新生成复用；服务器重启则全清。

### 验证

- ESLint 通过；浏览器实测积分牌渲染正常、无溢出（`scrollWidth ≤ clientWidth`）。

## 反馈 23：局域网访问下复制房间号失效

### 你的想法

> 在 http://10.4.91.32:5173 上访问，房间号链接复制有问题，怀疑没有把房间号放到链接后面；不行就恢复成只复制号码。

### 排查与实现

1. **根因**：`navigator.clipboard` API 只存在于**安全上下文**（https 或 localhost）。局域网 IP 是 http 非安全上下文，该 API 直接不存在——点复制什么都不发生。此前"地址栏没带 ?room="的现象则大概率是设备缓存了旧页面（旧版代码确实没有 URL 同步）。
2. **实现**：复制内容改为**纯房间号**（局域网对方在房号输入即可，最通用）；复制通道加 `execCommand('copy')` 兜底（临时 textarea 选中复制），http 非安全上下文也能真正写进剪贴板；chip 悬停提示改为"点击复制房间号"。地址栏 `?room=` 同步逻辑保留（localhost/https 场景仍可用）。
- 顺带修复：AI 状态行的"出错 N 次"显示在早前重构中被误删，已恢复。

### 验证

- `tsc` + ESLint 通过；已推送（f662229）。
